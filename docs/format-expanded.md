# 実IMGとDeep解析による追加形式観察

## 取得の確認

全IMGは31,486,640,128 bytes。全ファイルのSHA-256計算、先頭既知範囲と新たな5点の独立HTTP範囲の照合、録画領域全体の読み取り専用走査を実施。D101/D102の対を439,666個、録画LBA／CHグループを993個確認した。全ファイルの構造検証と、全映像を実際にデコードする検証は別である。送信者側の全体ハッシュは提供されていない。

## 音声

- 原版VA `0x4B52A0`（DirectSound作成）と呼出側`0x4213D0`／`0x428BF0`をDeepで逆コンパイル。
- WAVE_FORMAT_PCMを使い、格納されたサンプリングレート単位を100倍する。8 bit PCMの無音値は0x80。
- D103/D105録画メタデータの`0x16 LE16 ×100`がHz、`0x18`がチャンネル数、`0x19`がビット深度。今回の実データは80／1／8 → 8000 Hz／1ch／8bit。
- D101の映像実長は`0x1A6 LE32`。音声は映像を512 byte境界へ切り上げた直後、実長は`0x1BC LE32`。映像内の余白を音声と誤認しない。
- μ-law／ADPCM等を推測して適用しない。メタデータがない／未対応なら説明付きで拒否する。

## バイナリGPS・時刻

- 全IMGからASCII NMEA文は見つからなかった。GPSはD101内の独自ヘッダー。
- ヘッダー読込：`0x56F960`、テレメトリー配置：`0x56C510`、読込：`0x56D4D0`。
- カード時刻は`0x0A`からYY MM DD hh mm ss frameSlot。frameSlotは百分の一秒ではない。`0x1D LE16`に今回30。0x1E8の15をFPSにしない。
- slot 30と次秒slot 0の重複境界を最低1フレーム間隔へ単調化し、未知のタイムゾーンやUTCを作らない。整数の秒部分を先に引き、epoch秒Double同士の差で精度を失わないようにした。修正前は約0.1µs差の時刻が60,000 HzのMP4時刻で重複し、AVAssetWriterが-16364で停止していた。別の6 byte時刻`0x12`の意味は未確定。
- `0x26`衛星数、`0x27`fix raw、`0x28 LEi32`緯度、`0x2C LEi32`経度。座標単位は1/600000度。
- `0x56DE20`由来のTokyo→WGS84：Bessel a=6377397.155 / b=6356078.962818188、WGS84 a=6378137 / b=6356752.314245179、ECEF平行移動(-147,+506,+687)m。
- `0x30 LEi16`は原版変換内で×0.001、`0x32 LEu32`は×0.036 km/h。座標系手動切替も実装。

## 未解釈のテレメトリー

`0x46/0x48/0x4A`と`0x50/0x52/0x54`のLE符号付き16 bitを加速度／ジャイロ候補のraw値として表示。物理スケール、軸、校正は未確定。`0x18`も原版のイベント区分との対応は確定していない。意味の不明な値を常時／イベント／履歴と分類しない。

## 360°表示

H.264 2560×1080に前後の魚眼が横並び。Metal上の標準等距離射影で二眼から視線方向へ再投影し、オーバーラップをブレンドする。前後の回転、中心、半径、レンズFOVを手動調整できる。

工場のレンズ多項式・光学校正・全機種パラメーターは復元できていない。標準モデルを「メーカー補正済み」「Windows版と完全一致」とは扱わない。
