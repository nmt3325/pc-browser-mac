# 形式の観察記録

適用範囲は提供された`YP_FORMAT_1.01`の取得済み範囲です。全機種への一般化はしていません。

## ソフトウェア側の根拠

- PC Browser.exe 1.9.60.0のSHA-256：`19aa4d38e41285f24594b82654108065698f8401fe40e845b7a9b65c6a858884`
- Craft Anything CLI 0.6.1、`--deep --project investigation.cany`を使用。
- 0x487250：LBA×512に基づくセクター読み取り。
- 0x5160A0：旧形式の管理領域LBA `0xE37BA`を使う経路。
- 0x53AF80／0x53B150：実行時のフレームLBAの次のセクターから、サイズをセクター単位へ切り上げて動画データを読む経路。
- 0x5439C0／0x544970のD103／D105は、実データ上のD101／D102各映像パケットと区別する。ソフトウェアのみで「frame header」と仮称した構造を、そのまま映像ペイロード長の根拠にしない。

## 実データと独立照合したパケット

512 bytes／little endian。D101の開始ヘッダーとD102の終了ヘッダーは、先頭DWORDのmagic以外の508 bytesが一致しました。

| Offset | 観察と実装での扱い |
|---|---|
| 0x000 | 開始`0xFFFFD101`、終了`0xFFFFD102` |
| 0x004 | パケットの連番。末尾0x1FCと一致を要求 |
| 0x008 | チャンネルの生値。物理カメラ数とは断定しない |
| 0x009 | 観察範囲で2がI開始、3が後続フレーム。全形式では未検証 |
| 0x00A–0x00F | 年下2桁・月・日・時・分・秒らしき値。カード時刻として表示し、UTCとは解釈しない |
| **0x1A6** | **非アラインのLE32映像バイト長**。99パケットをこの長さで切り出すと、セクター単位抽出と同一のデコード結果になった |
| 0x1AC | 前後ヘッダーを含むセクター数。終了LBA−開始LBA＋1と照合 |
| 0x1B0 | 自身の開始ヘッダーLBA。実際の位置との一致を要求 |
| 0x1B4 | 終了ヘッダーLBA。入力サイズと上限走査範囲を検査 |
| 0x1B8 | 録画コンテナーの参照LBAとしてグループ化に使用 |
| 0x1BC | セクター境界後の補助データ長として観察。音声コーデックは未確定 |
| 0x1E8 | 観察範囲で15。**fpsとは解釈しない**。カード時刻では秒あたり約30パケットが観察された |
| 0x1FC | 連番の複製 |

映像ペイロードは`(開始LBA + 1) × 512`から0x1A6のバイト数だけ読む。元IMGは変更しない。
動画の先頭はAnnex Bで、SPS/PPSを使いAVCCに変換してVideoToolboxへ渡す。
観察範囲の映像はH.264 Main、2560×1080。FFmpegの厳格デコードとmacOS VideoToolboxを独立に使用して99フレームを照合した。

## チェックサムと未確定事項

管理領域単体の成分和を、保存された集約チェックサムと比較して「破損」と判定してはいけない。
集約式の全構成・全機種での検証は未完了で、本アプリは集約チェックサムの正当性を保証しない。

補助データ、GPS／IMU、循環記録の巻き戻り・連番ラップ、厳密な動画時刻同期、360°投影とレンズ補正のパラメーターは未確定。
