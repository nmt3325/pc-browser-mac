# 記録設定のカード上の保存形式（Q-01系・単一チャンネル）

原版PC Browser 1.9.60.0の「記録設定」ダイアログ（ダイアログ130）を、Wine上で実際に操作し、原版が書き込もうとしたセクターを書き込み前後で比較して求めた形式です。
推測で埋めた項目はありません。ここに載せていない値（他機種のダイアログ131–139）は未解析で、アプリは認識できない形式を書き込まず拒否します。
実カード・実機の値、セクター番号、日時、SDカードID、パスワードはこの文書にもテストにも含めません。表の値はすべて形式の説明用の一般的な値です。

## 場所

| 役割 | 位置 |
|---|---|
| 管理セクター（control） | 最後のパーティションの直後のセクター S（`YP_FORMAT_1.01__`識別子を持つ） |
| チャンネル設定セクター（channel） | S + 1 |
| チャンネル設定セクターのバックアップ | 履歴領域の最終セクター（領域表の6語目）+ 1 |
| 管理セクターのバックアップ | 履歴領域の最終セクター + 2 |

バックアップはディスク末尾からではなく、領域表の履歴領域の直後にあります（実カードではその後ろに約8 MBの領域が続くが、用途は未確認で、この版は読まず書かない）。
原版は設定保存のたびにこの4セクターだけを書き換えます（バックアップはそれぞれ本体と同じ内容）。録画データ領域や他のセクターには書きません。
この版は4セクターの位置を領域表から求め、バックアップの管理セクターに識別子がない場合・チャンネル設定ブロックが本体と一致しない場合は書き込みを拒否します。

## 管理セクター（512バイト、リトルエンディアン）

| オフセット | 内容 |
|---|---|
| 0x00 | 世代番号の下位1バイト（下記） |
| 0x01–0x11 | 識別子 `YP_FORMAT_1.01__` + 0x00 |
| 0x12–0x13 | チェックサム（下記） |
| 0x14 | チャンネル数（単一チャンネル = 1。これ以外は拒否） |
| 0x20 | チャンネル設定ブロックの先頭（0x20–0x38がチャンネル設定セクターにも同じ内容で入る） |
| 0x21 + 8n | 録画レコード n（0 = 常時、1 = イベント前、2 = イベント後）：`0x0B`, パラメーター u16, 単位 u8, コマ数 u8, `0x00`, ウィンドウ u16 |
| 0x3A / 0x3B / 0x3C | 常時／イベント／履歴の上書き（2 = 上書き、1 = しない） |
| 0x3E | 録画方法（1 = 常時のみ、2 = イベントのみ、3 = 常時＋イベント） |
| 0x3F | 音声（1 = 記録、2 = しない） |
| 0x46 | Gセンサー（5 = 記録、4 = しない） |
| 0x47 | 簡単設定（2 = 簡単設定、1 = 個別、Gセンサーなしのとき0） |
| 0x48 / 0x49 / 0x4A | 衝撃／急発進・急ブレーキ／急ハンドル感度（1〜9。Gセンサーなしのとき0） |
| 0x50 | ビープ音（3 = 鳴らす、0 = 鳴らさない） |
| 0x54 / 0x97 | マルチバッテリー（接続 = 1 / 2、なし = 0 / 0） |
| 0x66–0x87 | SDカードID（ASCII、0終端、残りは0。24文字まで。原版は25文字以上を拒否） |
| 0x88 / 0x89–0x8A | パスワード：フラグ（0 = なし、1 = あり）と、リトルエンディアンの語 `3 × パスワード + 1639`（なしのときは0）。下記 |
| 0x90 | 履歴記録コマ数（0 = 標準、1 = 2倍） |
| 0x1BE–0x1D5 | 領域表（6語：常時開始／終了、イベント開始／終了、履歴開始／終了） |
| 0x1E0 / 0x1E4 / 0x1E8 と 0x1FF | 世代番号（4つの語と末尾の1バイトが同じ値） |
| 0x1EC–0x1FC | 識別子の写し |

上記以外のバイトは、読み出し時の値をそのまま書き戻します（機器固有の識別子等を含むため、変更も消去もしません）。

### 録画コマ数（パラメーター／単位／コマ数）

単位 1 = 毎秒、2 = 毎分、3 = 毎時。30コマ/秒 (10000/1/30)、15 (11000/1/15)、10 (12000/1/10)、5 (12000/1/5)、1 (14000/1/1)、2コマ/分 (14000/2/2)、1コマ/分 (14000/2/1)、12コマ/時 (14000/3/12)、6コマ/時 (14000/3/6)。
イベントレコード（1と2）は毎秒系のレートでは常時と同じレート、それより遅いときは1コマ/秒です。イベントのみの録画では、原版は上位5つ（30・15・10・5・1コマ/秒）だけを選択肢に出します。
ウィンドウは「イベント前」「イベント後」の秒数 × 有効コマ数/秒です（10+10、12+8、15+5、18+12、20+10、20+20、25+15、30+10、30+20、25+25、30+30秒）。

### パスワード

「パスワード」欄（4桁の数字、1000〜9999）は、フラグ1バイト（0x88）と語（0x89–0x8A）に保存されます。パスワードを持つカードを開くと、原版はダイアログ106で入力を求め、
間違い・キャンセルのときはカードを読み込みません。パスワードはアプリ上の関門であり、録画データは暗号化されていません（制御セクターだけで形式を確認できた理由です）。
欄の判定は原版の保存ボタン押下時と同じです：空欄 = パスワードなし／5文字以上 =「4 文字以内で入力してください。」／1000〜9999の数字以外 =「パスワードは1000～9999の範囲で入力してください。」。
パスワードを設定・変更したときは「パスワードが変更されています。確認のためもう一度パスワードを入力してください。」で再入力を求め、一致しなければ「パスワードが間違っています。」で保存を中止します。
パスワードを空にして保存するときは「パスワードがクリアされます。よろしいですか？」で確認します（文言は原版のまま）。
形式の確認はQ-01系（クラス81）だけです。保存形式にない値（フラグが0・1以外、語が `3n + 1639` でない、なしなのに語が残っている等）は推測せず読み取りも書き込みも拒否します。

### 初期設定に戻す

ダイアログの「初期設定に戻す」は、すべてのコントロールを変えてから押して観察した結果、記録方法 = 常時＋イベント、録画コマ数 30コマ/秒、イベント記録時間 10+10秒、音声あり、履歴記録24時間（標準コマ数）、
常時・イベント・履歴の上書きとビープ音あり、Gセンサーあり・簡単設定・感度5にします。SDカードID・パスワード・マルチバッテリーには触らず、日時と設置角度検出のチェックは外れます。
工場出荷カードの値（イベント30+30秒、履歴168時間）とはイベント記録時間と履歴記録時間が異なるため、`RecordingSettings.factoryDefault` とは別に扱っています（`--set reset=defaults`）。

### チェックサム

`2 × (管理セクターの全バイト（0x12–0x13を除く）の和 + チャンネル設定セクターの全バイトの和) mod 65536` をリトルエンディアンで0x12–0x13に保存します。
バックアップのセクターも同じ内容なので同じ値です。原版が書いたセクター（単独・複合の変更、領域表を変える保存を含む）のすべてでこの式と一致しました。

### 領域表

履歴記録の長さは 時間（24／168／480）× 1800セクター/時（2倍コマ数のとき ×2）。履歴領域の最終セクターは変えず、
`js = 履歴最終 − 履歴セクター数 + 1` を履歴開始、`js − 1` をイベント領域の最終にします。
常時＋イベントのとき常時領域は先頭から `12 × floor(js × 71 / 1200)` まで、イベント領域はその直後からです。
イベントのみのときは常時領域が空（0, 0）でイベント領域が先頭から、常時のみのときはイベント領域が空で常時領域が `js − 1` までです。
録画方法・履歴時間・履歴コマ数のいずれかを変えたときだけ領域表を書き換えます（原版はこのとき録画データの消去を確認します）。

### 世代番号

領域表を書き換える保存のとき、世代番号が1（工場値）なら2に上げ、2以上ならそのままです（開始値1・2・5で確認）。領域表を変えない保存では変わりません。値0・0xFFで始まる場合の挙動は未確認です。
このとき3つのカウンター（0x1E0・0x1E4・0x1E8）も新しい世代番号と同じ値になります。

「録画データ削除」「記録設定データ初期化」は別の規則です。世代番号を1上げ、カウンターは読み込まれていた領域の最新の周回世代＋1にします（領域がなければ `max(元の値, 新しい世代番号)`）。
録画データは消さず、読み取り側がそれより古い録画を一覧に出さなくなります。詳細と読み取り側の規則（世代番号1でだけ確認）は [recording-data-operations.md](recording-data-operations.md) にあります。

## CONFIGフォルダーの指示ファイル

FAT16パーティションの `CONFIG` フォルダーに、原版は次の2つの指示ファイルを作成・削除します。

| ダイアログ項目 | 動作 |
|---|---|
| 日時：「設定する」 | チェック時の保存で `CONFIG\TIME.INI`（`[SET]` CRLF `LOCALTIME=YYYY.MM.DD;HH:MM:SS`、36バイト、末尾改行なし、保存時のピッカー値）を作成／上書き。外して保存すると削除 |
| 設置角度検出を実行 | チェック時の保存で空の `CONFIG\SELFADJ.INI` を作成、外して保存すると削除 |

ダイアログを開いたとき、各ファイルが存在すれば項目はチェック済みで表示されます（日時ピッカーはファイルのLOCALTIME、なければ現在時刻）。
これらのファイルを実際のレコーダーがどう扱うかは、ここでは確認できていません（原版が作るファイルと同じ内容を作るだけです）。

## 機種の判定（37機種・6ダイアログクラス）

原版の「使用機種」一覧は37機種です。カードの制御セクターのオフセット0x1DCの1バイトが機種コード（レコーダーが書く値）で、原版はこのコードでウインドウ表題（`PC Browser[機種名]`）と記録設定ダイアログの種類を選びます。
一覧の位置と機種名は原版の機種テーブルから読み、コードは複製カードの制御セクターのこのバイトを書き換えて、表題と設定ダイアログが変わるのを観察して求めました（`DeviceModelTable`、実カードの値は載せていません）。

ダイアログの種類（原版内部のクラス番号）は6つで、同じクラスの機種は同じ配置のダイアログを開きます。測定した大きさ（96 dpi、幅×高さ ピクセル）：

| クラス | 機種数 | 機種 | 大きさ |
|---|---:|---|---|
| 78 | 1 | SN-HQ90d | 1104×917 |
| 80 | 11 | BDR-1, BDR-S1, BU-DRR403/603T/405/605T/615T, BU-DRB305, FA1001/1002/2001 | 1079×1009 |
| 81 | 5 | Q-01, Q-02, Q-03, SRZ-01, Q-04 | 1079×901 |
| 123 | 1 | S20 | 1104×1100 |
| 127 | 15 | BU-DRHD320/421/620T/330/431/630T/635T/640T/645T と Ver.2 の4機種, FDR-800, FDR-810 | 1079×1119 |
| 147 | 4 | FDR-820, FDR-820 m2, FDR-820AI, FDR-900 | 1482×1056 |

Mac版はこの判定で、開いたカードの機種名とウインドウ表題、メニューの機種選択を合わせます。**このページの保存形式を実際に解析したのはQ-01系（クラス81）の1機種だけです。**
記録設定シートが書き込みを許すかどうかは機種ではなく、この形式の検査（識別子・バックアップの一致・チェックサム・チャンネル数1）で決まります。
他のクラスのカードが同じ形式かどうかは確認しておらず、Q-01系以外のカードにこの版の設定書き込みを使うことは勧めません。

## この版（Mac）の書き込み方針

- 原本のカード、マウント中のボリューム、読み込んだIMGには書き込みません。「記録設定」は新しいIMGコピーを作り、コピーにだけ書きます（APFSではクローン、それ以外は全体コピー）。
- 書き込み前に4セクターの内容が読み取り時と同じことを確認し、書き込み後に読み戻して一致を検証します。指示ファイルはFAT16（クラスター数4085以上、FATコピー一致）のみ対応し、書き込み後に再読み込みして検証します。
- 認識できない値・チェックサム不一致・領域表が標準式と異なる場合の領域変更は拒否します。
- コマンドライン：`--settings-show <image>`、`--settings-apply <image> --out <新しいimg> --set key=value …`（`--plan-only`で書かずに4セクターのSHA-256を出力）。
- 録画データ削除・記録設定データ初期化も同じ方針（新しいコピーの4セクターだけを書く）です：`--erase-recordings <image> --erase-kind delete|initialize --out <新しいimg> --confirm-erase`（`--plan-only <json>`、`--report <json>`）。[recording-data-operations.md](recording-data-operations.md)
