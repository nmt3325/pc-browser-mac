# Validation gaps — what has *not* been verified

This page separates what the Mac port has been shown to do (see `validation-history.md`, `validation-full-port.md`, `validation-bak.md`, `history-report.md`, `kml-export.md`) from what has **not** been verified. Nothing on this page may be read as "works"; each row names the missing evidence. A row leaves this page only when the evidence exists and is linked from the validation documents.

**CI status:** build 16 (commit `5eea4d09`) passed in run #146: unit tests (408, 0 failures), the signed app build, the extracted-package check, the GUI self-check (including the zero-filled-video notice check and the event-aware flow) and packaging; the pre-release `v0.2.0-beta.3` was built from commit `2d4a62d0` in run 43626122478 (408 tests) and its exact assets were then verified on a Mac (`validation-full-port.md`, "Build 16"). Earlier: runs #132/#133 (build 15, 16分割表示, 387 tests, release `v0.2.0-beta.2`); run #130 and a manual diagnostic workflow failed at hosted-runner assignment (an availability problem of the account, not of the code) and run #131 failed to compile (`projection.mode=.perspective`, fixed in `b600745f`); run #138 failed twice at the GUI self-check's audio/video sync on the slow hosted VM and was fixed in the player (`TODO.md`, baseline). The code written after build 16 (映像抽出, the build-17 candidate) had no CI result when this paragraph was written; see `TODO.md` for its status.

Earlier verified CI: run #126, 378 tests, 0 failures, signed app, extracted-package check, GUI check and settings smoke (including delete / initialise on copies) passed. The exact artifacts of build 13 (run #82), build 14 (run #128), build 15 (`v0.2.0-beta.2`) and build 16 (`v0.2.0-beta.3`) were run on a real Mac (Apple Silicon, macOS 15.7.7) with real data from an image of the sample card: lists, history report CSVs (byte-identical to the Python reference), KML (12th decimal only), the MP4/AVI/PNG/print/report-PDF exports of a real event recording, the BAK writer, delete/initialise on clones and the destination-full behaviour of the MP4/AVI/BAK exports; in build 16 also the packaged GUI check on real media (the event recording, and — with payload copied into a scratch copy of the Mac's structural image — continuous recordings #23 and #11). The earlier statement that the card's continuous recordings carry **no** video was an artifact of the Mac's header-only copy and is corrected in `validation-full-port.md`. Still **not** run on a Mac: AVI beyond 4 GiB with real video, the payload of the other 16 continuous recordings, the physical SD path, macOS 14 and the Intel GUI. Everything else the newest builds added is verified by CI (synthetic data, differential tests against independent reference scripts) and by comparisons made on the Linux machine that runs the original application.

## Settings, password and format operations

Tracked in `settings-format.md`, `recording-data-operations.md` and `destructive-operations.md`. In short: every setting field the Mac port writes was derived from the original's own writes on a scratch copy and is limited to the Q-01 class. The password (set, change, clear, ask on open), 録画データ削除 and 記録設定データ初期化 are implemented for that class on **new image copies only**; the reader rule behind 削除 is verified at card generation 1 only (see above). The settings of the other five dialog classes, week-timetable, person-detection and Wi-Fi settings, the model-specific initialisation (format flow), quick/full format and firmware update are analysed in part or guarded but never executed against an original medium. The original's format flow was observed only up to the partition table, the FAT16 boot sector and the first FAT sector (a Wine stub then stopped it).
